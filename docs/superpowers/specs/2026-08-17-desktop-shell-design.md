# 设计规格：fan-files 桌面壳（子项目 ①）

> 日期: 2026-08-17 | 分支: `feat/desktop-app` | 状态: 待实施
> 决策方式: 与 kentnf 逐项讨论确定（导航/首页/数据集页经浏览器视觉伴侣逐屏选定）

---

## 一、背景与目标

fan-files 目前是纯命令行工具。产品落脚点 = **下载即用的桌面程序**（目标用户：
Windows 上的生物研究者/学生，非程序员）。愿景闭环：打开界面 → 指定目录 → 配模型
（或使用崖州湾实验室试用服务）→ 一键扫描 → 自然语言查"我有什么数据" → 选中数据集
点 Share 发给同事 → 对方在自己的程序里收到数据。认证、配置、更新、共享全部在界面内
完成，省掉做网站；共享即传播。

本规格覆盖**子项目 ①：桌面壳**——让"点目录就能用"先成立。其余子项目（② P2P 传输库、
③ Share 链路、④ 试用配额服务）各自独立设计，本规格仅在界面处为其预留入口。

## 二、子项目划分（总愿景）

| 子项目 | 内容 | 状态 |
|--------|------|------|
| ① 桌面壳 | Tauri GUI：扫描/浏览/搜索/设置/更新 + 托盘常驻 | **本规格** |
| ② P2P 传输库 + CLI | magic-wormhole 传输（send/get/log） | 设计已冻结（fan-files-p2p-transfer-design.md），待实施 |
| ③ Share 链路 | 界面内配对码/邮件/链接通知 + 接收流程 | 依赖 ①（详情面板落点）+ ② |
| ④ 试用配额服务 | 182 服务器：机器码注册 + token 用量计量 | 依赖 ①（账号页落点） |

## 三、已确认决策（含理由）

| # | 决策 | 选择 | 理由 |
|---|------|------|------|
| 1 | 导航结构 | A 侧边栏 | 页面多了不乱；每个功能区一个图标+名称，新手可认；后续加页自然 |
| 2 | 首页 | A 状态仪表盘 | 一眼看到"我盘上有多少数据"；扫描按钮永远在；首次空状态引导明确 |
| 3 | 数据集页 | A 表格列表 | 千级数据量（orders 上 1,453 个）不慌；排序/筛选天然支持 |
| 4 | 前端栈 | React + TypeScript | 生态最大，AI 辅助维护时生成质量最高 |
| 5 | 平台 | Windows + macOS + Linux 三平台 | Windows 是主目标；Mac 为开发机天然可用；Linux 服务实验室服务器用户 |
| 6 | v1 范围 | 四页 + 托盘常驻 | 完整闭环；托盘承载"后台可用"心智 |
| 7 | 引擎接入 | 子进程 sidecar | 引擎与壳解耦；复用现成 share HTTP API 与 CLI；CLI 修 bug GUI 自动受益 |
| 8 | 后台自动扫描 | v1 定时增量扫描（默认每小时） | YAGNI：连续文件监听（watcher）不稳定，留 v1.1 |
| 9 | 配置与索引 | GUI 与 CLI 共享同一 config.toml 与 index.db | 单一事实源；CLI 老用户打开 GUI 直接看到自己的索引 |

## 四、架构

```
┌─ Tauri 应用（单安装包，三平台）────────────┐
│  React+TS 前端（四页 + 托盘）              │
│  Rust 后端薄层：子进程管理 + 进度流 + 配置读写 │
└──────┬──────────────────────┬─────────────┘
       │ spawn / stderr 流     │ HTTP fetch（127.0.0.1）
┌──────▼─────────┐   ┌─────────▼──────────────┐
│ fan-files CLI  │   │ fan-files-share（常驻）  │
│ 点扫描=spawn    │   │ /datasets /files        │
│ discover，读    │   │ /facets /stats（已有）   │
│ 日志行做进度条  │   │ + /search（本分支新增）   │
└────────────────┘   └────────────────────────┘
```

- **sidecar 打包**：Tauri sidecar 机制打包 `fan-files` 与 `fan-files-share` 两个二进制（三平台各自构建）
- **进程生命周期**：GUI 启动时拉起 share 子进程（常驻）；退出/托盘时保留 share（托盘常驻模式）或随 GUI 退出（用户设置）
- **端口**：share 默认固定端口，启动检测冲突则换随机端口（参数传给 GUI 前端）
- **配置与索引共享**：GUI 读写 `~/.fan-files/config.toml`；索引 `~/.fan-files/data/` 与 CLI 共用
- **引擎侧唯一改动**：share 新增 `GET /api/v1/search?q=…`（复用 Tantivy 全文索引 + 现有 facets 分页模式），约半天工作量

## 五、页面与组件

### 侧边栏
首页 / 数据集 / 搜索 / 设置 + 底部版本号。图标+文字，选中态高亮。

### 首页（状态仪表盘）
- 顶部：**📁 选择目录开始扫描** 主按钮（首次空状态时为大号引导按钮）+ 🔄 重新扫描
- 中部：三个统计卡（目录 / 文件 / 数据集，数据源 `/api/v1/stats`）
- 下部：最近发现列表（最新 N 个数据集，来自 `/datasets?order=recent`）
- 扫描中：主按钮区变为进度条 + 滚动日志区（discover stderr 原样渲染）

### 数据集页（表格列表）
- 表格列：名称 / 类型徽章（genome 蓝、transcriptome 橙等，色板同图规范）/ 物种 / 文件数 / 路径
- 类型筛选（`/facets`）+ 名称排序 + 分页（share 已支持 page/size/order）
- 行点击 → 详情弹层：物种、路径、资产列表、文件列表（`/datasets/{id}` + `/files`）
- 详情弹层内按钮：**📤 共享（v1 灰置，tooltip "即将推出"）**、📂 打开目录（系统文件管理器）

### 搜索页
- 大搜索框 → `GET /api/v1/search?q=…` → 结果复用数据集表格组件；空态提示示例查询

### 设置页
- **目录**：include/exclude 列表增删（写 config.toml）
- **模型**：endpoint / api_key / model 三个字段 + "测试连接"按钮（发一条最小 LLM 请求）
- **账号与崖州湾试用**：占位页（"即将推出"），预留子项目 ④ 落点
- **关于**：版本号 + 检查更新按钮（spawn `fan-files update`）

### 托盘
菜单：打开窗口 / 立即扫描 / 退出。托盘常驻 = 窗口隐藏后 share 进程与定时扫描继续运行。

## 六、数据流

1. **首次启动**：无 include 配置 → 首页空状态 → 系统目录选择器选目录 → 写 config.toml
   → spawn `fan-files discover` → stderr 进度行渲染 → 完成 → 刷新 `/stats`
2. **定时扫描**：托盘常驻期间每 N 小时（默认 1）自动执行与手动扫描相同的 spawn+进度流程
   （窗口隐藏时静默运行，出错写入托盘菜单提示）
3. **浏览/搜索**：前端 fetch 本地 share API 渲染，无额外链路
4. **更新**：设置页检查更新 → spawn `fan-files update` → 完成后提示重启应用

## 七、错误处理

| 场景 | 处理 |
|------|------|
| share 进程失联 / 启动失败 | 自动重试启动 1 次 → 全局错误横幅"引擎未运行，点击重试" |
| 扫描失败（LLM 未配置、目录不可读等） | discover stderr 原样进首页日志区 + 引导去设置页配模型 |
| 端口被占 | share 自动换随机端口，前端从后端获取实际端口，用户无感 |
| 未扫描（空索引） | 各页空状态引导去首页扫描 |
| sidecar 二进制缺失（损坏安装） | 启动检查 → 提示重新安装 |

## 八、测试策略

- **前端**：Vitest 组件单测——表格渲染/筛选/分页、空状态、进度条、错误横幅
- **Rust**：share `/search` 端点单测（沿用 `api/mod.rs` 现有测试模式）
- **集成冒烟**（脚本化）：起 share → 校验 `/healthz` `/stats` `/datasets` `/search` 返回
- **CI**：现有 GitHub Actions 加 Windows 构建目标（已有 linux + macos-arm64）
- **手动验收**：Mac 全流程（选目录→扫描→浏览→搜索→设置→托盘）；Windows 用 CI 产物在真机/VM 冒烟

## 九、明确不做（v1）

- Share 真实链路（配对码/邮件/链接）——子项目 ②③
- 试用配额/账号体系——子项目 ④
- 连续文件监听自动扫描（watcher）——v1.1
- 首次启动向导（onboarding wizard）——v1 用首页空状态替代，观察反馈后决定
- 内置本地小模型（离线模式）——留待评估，模型接入先只支持用户自配 endpoint

## 十、风险与开放问题

1. **Windows CI 构建**：Tauri Windows 目标需在 CI 配 windows runner；现有 release workflow 需扩展
2. **定时扫描与用户手动扫描并发**：需互斥（同一时间只允许一个 discover 进程），实现时用进程锁
3. **share `/search` 端点语义**：实现时先核对现有 `/datasets` 是否已支持 q 检索参数——若已支持则直接复用、不新增端点；否则新增 `GET /api/v1/search`（复用 Tantivy，响应格式与 `/datasets` 一致）
4. **托盘行为细节**（退出 vs 最小化到托盘）遵循平台惯例：Windows 点 X 收托盘，macOS 点 X 退出
